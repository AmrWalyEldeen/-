# نظام إدارة جداول معامل قسم علم الحيوان — Web v2

نسخة ويب عربية RTL لإدارة جدول المعامل، الهيئة المعاونة، هيئة الإشراف، النصاب، المقررات، الطباعة والحفظ.

## الجديد في v2

- تحديد **الساعات المستهدفة لكل درجة علمية** بشكل مستقل للهيئة المعاونة وهيئة التدريس.
- إمكانية وضع **نصاب استثنائي لعضو بعينه** عند الحاجة، بدل نصاب درجته الافتراضي.
- دليل مركزي للمقررات مع تحديد:
  - اسم/كود المقرر.
  - نوع البرنامج: برنامج عام أو برنامج خاص.
  - طريقة حساب الساعات: **داخل النصاب** أو **ساعات إضافية** أو **لا تُحسب**.
  - التخصص الافتراضي.
  - هل يحتاج إشرافًا افتراضيًا أم لا.
- تقارير الساعات تفصل بين **ساعات داخل النصاب** و**الساعات الإضافية**؛ الفرق عن المستهدف يعتمد على ساعات النصاب فقط.
- إضافة/تعديل/تعطيل المقررات.
- إضافة/تعديل/حذف أعضاء الهيئة المعاونة وهيئة التدريس واختيار الدرجة العلمية.
- إضافة/حذف جلسات ومعامل وتغيير اليوم والوقت والمادة والمعمل.
- الجدول النهائي يتحدث تلقائيًا من بيانات التوزيع.
- طباعة عربية RTL، مع عرض المعامل النشطة فقط.
- حفظ محلي LocalStorage أو حفظ مركزي باستخدام Supabase.
- سجل تعديلات عند استخدام Supabase.

## التشغيل السريع محليًا

يمكن فتح `index.html` مباشرة، أو تشغيل خادم محلي بسيط. في الوضع المحلي تحفظ التعديلات على نفس المتصفح باستخدام LocalStorage.

## النشر على GitHub Pages

1. أنشئ Repository جديد على GitHub.
2. ارفع **محتويات هذا المجلد** إلى جذر الـRepository.
3. من Settings → Pages اختر GitHub Actions كمصدر النشر.
4. Workflow الموجود في `.github/workflows/pages.yml` سينشر الموقع تلقائيًا.

## الحفظ المشترك باستخدام Supabase

للحفظ بين أكثر من جهاز/مستخدم:

1. أنشئ مشروع Supabase.
2. للمشروع الجديد شغّل `supabase/schema.sql` ثم `supabase/seed.sql` في SQL Editor.
3. إذا كنت ترقي نسخة الموقع القديمة، شغّل `supabase/migration_v2.sql` مرة واحدة بدل إعادة إنشاء الجداول.
4. أنشئ مستخدم Admin في Supabase Authentication.
5. عدّل `config.js` وضع `SUPABASE_URL` و`SUPABASE_ANON_KEY`، أو استخدم آلية Secrets/الـworkflow الموجودة بالمشروع حسب طريقة النشر.
6. افتح الموقع وسجّل الدخول، ثم استخدم زر الحفظ.

> لا تضع `service_role` key داخل الموقع أو GitHub Pages. المفتاح المناسب للواجهة هو anon/public key مع سياسات RLS الموجودة في schema.

## منطق النصاب والمقررات

### النصاب
من صفحة **إدارة المواد والأعضاء والنصاب** يمكنك إضافة درجة علمية وتحديد عدد الساعات المستهدفة لها. عند تغيير الرقم تتحدث تقارير الأعضاء تلقائيًا. ويمكن تحديد `target override` لعضو معين إذا كان له نصاب مختلف عن باقي نفس الدرجة.

### نوع المقرر
كل مقرر يملك `workload_mode`:

- `target` = داخل النصاب.
- `extra` = ساعات إضافية خارج النصاب.
- `excluded` = لا تدخل في حساب الساعات.

مثال: مقرر تابع لبرنامج خاص يمكن ضبطه على **برنامج خاص + ساعات إضافية**، فيظهر في الجدول والتكليفات بشكل عادي لكن لا يقلل الفرق المتبقي من النصاب الأساسي.

## إدارة البيانات

- **المقررات:** إضافة، تعديل، تعطيل/حذف حسب القيود المرجعية.
- **الأعضاء:** إضافة عضو جديد، اختيار درجته، وتحديد نصاب استثنائي إن لزم.
- **الجلسات:** إضافة مادة/معمل جديد وتحديد اليوم والوقت والمعمل والتكليفات.
- **الجدول النهائي:** عرض مشتق تلقائيًا؛ لا يحتاج إدخالًا مكررًا.

## الملفات المهمة

- `index.html` — واجهة التطبيق.
- `assets/app.js` — منطق النظام والحسابات والحفظ.
- `assets/styles.css` — التصميم والطباعة وRTL.
- `data/seed.js` / `data/seed.json` — بيانات البداية المدمجة.
- `supabase/schema.sql` — إنشاء قاعدة البيانات الجديدة.
- `supabase/seed.sql` — تحميل بيانات البداية.
- `supabase/migration_v2.sql` — ترقية قاعدة بيانات النسخة السابقة.
- `docs/DEPLOY_AR.md` — تعليمات النشر.
- `docs/DATA_MODEL_AR.md` — نموذج البيانات.
- `docs/UPDATES_AR.md` — ملاحظات التحديثات.

## النسخ الاحتياطي

من صفحة الإعدادات يمكن تصدير Backup بصيغة JSON واستعادته لاحقًا. يُنصح بأخذ نسخة قبل أي تعديل كبير في التوزيع.
